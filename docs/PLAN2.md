### Design facts the testbench relies on

Confirm these against `rtl/sync_fifo.v` before writing the scoreboard, and fix the plan if the RTL differs:

- Read output is **registered**: data is valid 1 cycle after an accepted `r_en`.
- **Write is blocked at full** and **read is blocked at empty**, even if the opposite operation happens in the same cycle.
- Parameters: `DEPTH` (>= 2, need not be a power of 2) and `DATAW`.

## 1. Phase 2: SystemVerilog testbench

**Branch:** `feature/sync-sv-tb` | **Files:** `tb/sync/` | **Est.:** 2 days

Keep it **UVM-free**: plain modules, an interface, tasks and queues, targeting Vivado xsim.

### 1.1 Architecture

```
              +-----------+      +----------+       +------------+
 random  ---> |  driver   | ---> |   DUT    | --->  |  monitor   |
 plan         | (w and r) |      |sync_fifo |       | (samples   |
              +-----------+      +----------+       | accepted   |
                                                    | transfers) |
                                                    +-----+------+
                                                          |
                                                    +-----v------+
                                                    | scoreboard |  queue model:
                                                    | + coverage |  push on write,
                                                    +------------+  pop + compare on read
```

### 1.2 Components

1. **Interface** (`sync_fifo_if.sv`) with a **clocking block**. Inputs are driven and sampled through it, which removes the drive/sample race in the original `tb1.v`.
2. **Driver:** separate write and read tasks.
   - Knobs for write probability and read probability (0-100%) using `$urandom_range()`.
   - Burst mode: N back-to-back writes, then idle.
3. **Monitor:** record a transaction only when it is **accepted** (`w_en && !full`, `r_en && !empty`), never when it is merely requested. This is the most common source of false scoreboard failures.
4. **Scoreboard:** `logic [DATAW-1:0] q[$]`.
   - Accepted write: `q.push_back(data_in)`.
   - Accepted read: `expected = q.pop_front()`, compared against `data_out` **one cycle later** (registered-read latency).
   - On mismatch: print time, expected, actual; increment the error count.
   - Every cycle: check `q.size()` against the DUT's `full`/`empty` flags.
5. **End of test:** print `TEST PASSED (N writes, N reads, 0 errors, seed=S)` or `TEST FAILED (...)`, and call `$fatal` on failure so scripts can detect it.
6. **Reproducibility:** accept `+seed=<n>` and `+test=<name>` via `$value$plusargs`. Print the seed at the start and seed all randomness from it, so a failing run can be replayed.
7. **Parameters:** `DEPTH` and `DATAW` come from the command line (xsim: `-generic_top`, or a `-d` define) so Phase 4 can sweep them.

### 1.3 Test list

| Test | What it checks |
|------|----------------|
| `reset` | After reset: `empty=1`, `full=0`, no X on outputs |
| `fill_to_full` | `full` asserts at exactly `DEPTH` accepted writes |
| `drain_to_empty` | `empty` asserts after exactly `DEPTH` reads; data order is FIFO |
| `overflow_attempt` | Extra writes at full are dropped and corrupt nothing |
| `underflow_attempt` | Extra reads at empty change nothing |
| `simul_rw_mid` | Simultaneous read+write at mid occupancy keeps data intact |
| `simul_rw_full` / `simul_rw_empty` | The documented policy holds at the boundaries |
| `wraparound` | Many multiples of `DEPTH` transactions so pointers wrap repeatedly |
| `random_balanced`, `random_write_heavy`, `random_read_heavy` | Long constrained-random traffic (e.g. 100k transactions per seed) |
| `reset_mid_traffic` | Reset during activity flushes the FIFO; the scoreboard queue is cleared too |

`+test=all` (default) runs them in sequence; `+test=<name>` runs one.

## 2. Phase 3: SVA and coverage

**Branch:** `feature/sync-sva-coverage` | **Est.:** 1 day

### 2.1 Assertions (`tb/sync/sync_fifo_sva.sv`)

Put them in a separate module and attach with `bind`, so the RTL stays clean.

```systemverilog
// sketch: adapt port names to sync_fifo.v
module sync_fifo_sva #(parameter DEPTH=8) (input clk, rstn, w_en, r_en, full, empty);
  a_not_full_and_empty: assert property (@(posedge clk) disable iff(!rstn) !(full && empty));
  a_reset_state:        assert property (@(posedge clk) $fell(rstn) |=> (empty && !full));
  a_write_clears_empty: assert property (@(posedge clk) disable iff(!rstn) (w_en && !full) |=> !empty);
  a_read_clears_full:   assert property (@(posedge clk) disable iff(!rstn) (r_en && !empty) |=> !full);
  a_no_x_flags:         assert property (@(posedge clk) disable iff(!rstn) !$isunknown({full, empty}));
endmodule

// in the testbench top:
bind sync_fifo sync_fifo_sva #(.DEPTH(DEPTH)) u_sva (.*);
```

Add a second set that compares the DUT flags against the **testbench's own occupancy counter** (computed from monitor transactions). This is an independent check, so a bug in the DUT's counter logic cannot hide itself.

### 2.2 Coverage

**First check what your xsim version supports.** Write a 10-line test with a `covergroup` and see whether it compiles and reports. Do this before designing around it.

If `covergroup` is not supported, use **hand-rolled coverage** in the monitor and print a table at the end of each run:

- Occupancy bins: `empty`, `1`, `middle`, `DEPTH-1`, `full`
- Events: write requested while full, read requested while empty
- Simultaneous r+w at each of {empty, mid, full}
- Write and read pointer wraparound counts (each at least K times)
- Print `COVERAGE HOLE: <bin>` if any bin is zero

**Be honest on the resume.** Say "functional coverage tracking" for what you actually measured. Claim covergroup-based coverage only if a tool really computed it.

4. `tb: add coverage bins to monitor`

## 3. Phase 4: Python automation

**Branch:** `feature/regression-script` | **File:** `scripts/run_sim.py` | **Est.:** 1 day

If `scripts/` already holds a regression script from another project (e.g. your RISC-V flow), copy its xvlog/xelab/xsim pattern rather than starting from scratch.

### 4.1 Interface

| Flag | Meaning |
|------|---------|
| `--seeds N` | Number of random seeds per configuration (default 20) |
| `--test NAME` | One test, or `all` (default) |
| `--depth D` / `--dataw W` | Run a single configuration |
| `--sweep` | Parameter sweep: `DEPTH` in {2, 3, 8, 16} x `DATAW` in {1, 8, 32} |

### 4.2 Behavior

1. **Compile** with `xvlog -sv` and `xelab` using `tb/sync/filelist.f`. Output goes in `build/` (git-ignored). Recompile only when the config changes.
2. **Loop** over config x seed. Run `xsim` in batch mode, passing `+seed` and `+test`, and save each log under `build/logs/`.
3. **Parse** each log for `TEST PASSED`, `TEST FAILED`, `COVERAGE HOLE` and assertion failures. A run with none of the PASS lines counts as a failure (covers hangs and crashes).
4. **Summarize:** print a table per configuration, write `docs/results.md`, and **exit non-zero** on any failure.
5. **Replay hint:** on failure, print the exact command to reproduce it (config, test, seed).
6. **Timeout** each simulation (e.g. 5 minutes) so a hang cannot stall the regression.

Example output:

```
sync_fifo regression: 12 configs x 20 seeds = 240/240 PASS | coverage holes: 0
```

### 4.3 Suggested commit sequence

1. `scripts: add run_sim.py skeleton with argparse`
2. `scripts: add xvlog/xelab compile step with generics`
3. `scripts: run xsim per seed and capture logs`
4. `scripts: parse logs for PASS/FAIL/COVERAGE HOLE`
5. `scripts: add --sweep over DEPTH and DATAW`
6. `scripts: write results table to docs/results.md`
7. `scripts: add timeout and replay command on failure`

### 4.4 Done when

- [ ] `python scripts/run_sim.py --seeds 20 --sweep` passes everywhere from a clean checkout.
- [ ] A deliberately broken RTL makes the script exit non-zero and print a replay command.
- [ ] `docs/results.md` is generated and committed.
